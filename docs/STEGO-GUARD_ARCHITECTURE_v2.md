## 1. Видение и назначение

Stego-Guard — система защиты цифровых документов от подделки, несанкционированного
редактирования и утечек. Первый прикладной домен — верификация сканов избирательных
протоколов и иных юридически значимых документов.

Система решает три задачи:
1. **Внедрение скрытой метки** (watermark) в документ при выпуске/публикации,
   связывающей файл с его содержимым и контекстом (код содержимого, ID участка).
2. **Проверку подлинности** любой копии документа: извлечение метки и сверка
   с реальным содержимым файла.
3. **Локализацию вмешательства**: тепловая карта зон документа, изменённых
   после внедрения метки.

Ключевой принцип: метка не видна человеку, устойчива к пересылке через
мессенджеры и JPEG-сжатию, и позволяет точно сказать — «файл изменён,
и вот где именно».

## 2. Архитектурный обзор (реализовано)

┌──────────┐   HTTP/REST   ┌──────────────┐   gRPC (внутр. сеть)   ┌─────────────┐
│ FRONTEND │ ────────────► │ API GATEWAY  │ ─────────────────────► │ ML-SERVICE  │
│ React/TS │ ◄──────────── │  Go (Fiber)  │ ◄───────────────────── │   Python    │
│  nginx   │               └──────────────┘                        └─────────────┘
└──────────┘                  порт 8080                                порт 50051
   порт 80
                        Все три сервиса — Docker-контейнеры,
                        единая внутренняя сеть (deployments/docker-compose.yml)

**Принципы:**
- Go-гейтвей — единственная точка входа наружу (HTTP); ML-сервис порт наружу
  не публикует, доступен только внутри сети compose (DNS-имя сервиса).
- Контракт — proto/stego.proto (пакет stego.v1, сервис StegoService:
  EmbedWatermark, VerifyDocument). Генерация: grpcio-tools (Python),
  protoc-gen-go через Docker-контейнер (на машинах с Device Guard).
- Конфигурация — только переменные окружения.
- Аутентификация в Фазе 1 отсутствует (внутренний контур); появится в Фазе 3.

## 3. Компоненты системы (как реализовано)

### 3.1. Frontend (React 18 + TypeScript + Mantine v7 + Vite)
- Режимы «🔒 Защитить» / «🔍 Проверить» (SegmentedControl), ввод ID участка.
- UploadZone: drag&drop, приём PNG/JPEG, клиентская валидация типа.
- ResultCard: вердикты AUTHENTIC / TAMPERED / NO_WATERMARK, BER, SHA-256
  документа (с копированием), heatmap (base64-PNG из ответа API).
- Скачивание защищённого файла через blob-URL.
- Структура: App.tsx — главный экран (состояние и оркестрация),
  components/{UploadZone, ResultCard, HashDisplay}, api/client.ts,
  types/api.ts. Сборка мультистейдж Dockerfile → nginx (прокси /api → гейтвей).

### 3.2. API Gateway (Go 1.27)
- Эндпоинты: POST /api/v1/embed (multipart: file, user_id), POST /api/v1/verify,
  GET /healthz.
- Валидация по магическим байтам (PNG/JPEG), лимит 25 МБ (BodyLimit).
- gRPC-клиент: блокирующий Dial с таймаутом 5 c, RPC-дедлайн 30 c.
- Аудит: JSON-строки в stdout (op, sha256, user_id, статус).
- Graceful shutdown (SIGINT/SIGTERM). go.mod: module github.com/lgr1dthebe4t22/stego-guard/api-gateway.

### 3.3. ML-Service (Python 3.13, PyTorch, PyWavelets, OpenCV)
- **Внедрение (Фаза 1 — классический DSP):** DWT (Haar) → квантование
  коэффициентов субполос LH/HL с шагом Δ=20; каждый бит — группа из 5
  коэффициентов (усреднение против шума JPEG). Метка внедряется дважды,
  копии разнесены по изображению.
- **Payload (71 байт = 568 бит):** магия "SG" + версия схемы (преамбула,
  24 бита) + код содержимого (16 байт) + user_id (32 байта) + CRC32.
- **Код содержимого:** 8×8-сетка субполосы LL, 2 бита/ячейка. Сравнение
  на верификации — расстояние Хэмминга ≤ 2 ячеек. (sha256 невозможен:
  шум uint8-округления ±2 неустраним при любом шаге квантования.)
- **Верификация:** извлечение двух копий → BER = их расхождение; сверка
  преамблы с эталоном (отличие «нет метки» от «метка уничтожена»);
  разбор payload (CRC), сравнение кода содержимого.
- **Дерево вердиктов:** преамбла не сошлась → NO_WATERMARK; payload цел и
  код совпал (≤2 ячейки) → AUTHENTIC; иначе → TAMPERED (+ heatmap:
  маска расхождений копий, наложенная на документ).
- **Защита от перезащиты:** перед embed проверяется преамбула; защищённый
  файл отклоняется со статусом EMBED_ERROR_INVALID_IMAGE.
- gRPC-сервер: ошибки превращаются в статусы контракта, не вылетают.

### 3.4. Тестирование
- 11 юнит-тестов (pytest): roundtrip, payload, код содержимого, вердикты,
  атаки (JPEG q90/q70, ресайз).
- e2e: ml-service/scripts/e2e_check.py — 5 проверок через HTTP-гейтвей
  (embed→AUTHENTIC, подделка→TAMPERED+heatmap, чистый файл→NO_WATERMARK).

### 3.5. Хранилища (Фаза 1)
Состояние не хранится (stateless); PostgreSQL — Фаза 4.

## 4. План реализации (актуальный)

### ФАЗА 1 — Контракт и скелет ✅ ЗАВЕРШЕНА
proto-контракт; ML-сервис с DWT-пайплайном; Go-гейтвей; фронтенд;
e2e-тест; Docker Compose; блок повторной защиты.

### ФАЗА 2 — ML-ядро (нейросетевой кодек)
- Шаг 8: датасет синтетических документов (генератор сканов) + симулятор
  атак (JPEG-качества, ресайз, кроп, поворот) — ml-service/data, dwt/attacks.py.
- Шаг 9: Encoder-Decoder на PyTorch (encoder/model.py, layers.py, train.py).
  Loss = ошибка извлечения бит + незаметность (L1/LPIPS) + стойкость
  (атаки на лету). Обучение — Google Colab / Kaggle (GPU) → веса
  models/stego_net_v1.pth. Интеграция в server.py — без изменения контракта.
- Шаг 10: evaluate.py — BER под атаками, PSNR/LPIPS; сравнение с Фазой-1;
  тюнинг порогов config.py по цифрам.

### ФАЗА 3 — Безопасность
- JWT-аутентификация, роли (operator/auditor/admin); ключи в env.
- TLS (пилот: самоподписанный; наружу — reverse proxy).
- API-харденинг: rate limiting, CORS-политика, единый формат ошибок
  без утечки внутренностей.
- Файлы: антивирусная проверка (опц.), безопасный рендеринг.
- Секреты: вне репозитория; аудит: подпись записей, защита от подделки логов.
- Зависимости: npm audit fix, pip audit, обновления.

### ФАЗА 4 — Production (+ оформление)
- PostgreSQL: реестр documents (id, код содержимого, user_id, дата),
  verifications (вердикт, BER, инициатор), users (роли).
- Пакетная верификация через очередь (NATS/RabbitMQ); метрики Prometheus;
  healthchecks; бэкапы.
- PDF: рендеринг страниц (PyMuPDF) → защита страниц как растровых.
- Оформление: heatmap со слайдером прозрачности, история проверок,
  логотип/брендинг, мобильная адаптивность, светлая/тёмная тема.
- Graceful shutdown Python-сервиса; gRPC healthcheck для compose.

## 5. Модель данных (Фаза 4)

documents: id (uuid), код содержимого (16 байт), формат, размер, user_id,
дата защиты.
verifications: id, document_id (nullable), код проверяемого файла, вердикт,
BER, дата, инициатор.
users: логин, хэш пароля, роль.

---

## 6. Безопасность (целевая, Фаза 3)

- Транспорт: TLS на reverse-proxy; внутренний контур — доверенная сеть.
- JWT с ролями; секреты — только в переменных окружения.
- Магические байты + лимиты + запрет исполняемых типов (уже реализовано).
- Формат payload не публикуется; без модели извлечение метки невозможно
  в разумное время.
- Rate limiting на verify (анти-брутфорс верификации).
- Подпись/неизменяемость аудита.

---

## 7. Развёртывание

- Docker Compose (deployments/): `docker compose up -d` — три сервиса,
  внутренняя сеть stego-net, DNS-дискавери сервисов.
- ML: python:3.13-slim + libgl1 + libglib2.0-0 (OpenCV) + CPU-torch.
- Gateway: golang мультистейдж, статический бинарник (CGO_ENABLED=0).
- Frontend: node-сборка → nginx:alpine, прокси /api → api-gateway:8080.
- Фронт: порт 80, гейтвей: 8080, ML наружу не публикуется.

---

## 8. Масштабирование (пост-Фаза 4)

Gateway stateless → реплики за балансировщиком. ML-сервис N+1. Очередь
для массовой проверки (тысячи протоколов). Graceful degradation:
при недоступности ML — «в обработке».

---

## 9. Риски и ограничения

- Сильное пережатие соцсетями — граница стойкости; решается обучением
  с атаками на лету (Фаза 2) и тюнингом ёмкости/незаметности.
- Печать + повторное сканирование необратимо разрушает метку → вердикт
  «изменён»; это корректно для модели угроз (копия ≠ оригинал).
- Пока только растровые форматы; PDF — Фаза 4.
- Юридическая значимость: система — инструмент экспертизы,
  не самостоятельное доказательство.

## Приложение А. Глоссарий

- DWT — дискретное вейвлет-преобразование; субполосы LL/LH/HL/HH.
- BER — bit error rate; здесь: расхождение двух копий метки (0.0–1.0).
- Преамбула — первые 24 бита payload (магия «SG» + версия), константа формата.
- Код содержимого — 8×8-сетка LL, 2 бита/ячейка (16 байт), пороговое
  сравнение ≤2 ячеек.
- Heatmap — маска расхождений копий метки, наложенная на документ.
